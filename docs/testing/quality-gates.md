# TapScene（点演）v0.1 架构阻断风险审查

日期：2026-10-09。基线：完整产品规格 v0.1（F01–F29、A01–A16）。这是设计审查与待执行门禁，不是实现、安全测试或真机验收通过报告。以下 10 项应进入 proposals PR，并落实到模块负责人、测试语料和发布证据；不能以“采用某框架”代替验收。

## 10 项优先阻断风险与门禁

### R01 本地 OCR 不等于无第三方联网
- 风险：打包模型解决首次离线可用，不自动解决 SDK 遥测、模型下载、崩溃采集或联网后补传。ML Kit 官方说明本地处理输入，但 Android SDK 仍采集诊断/使用信息。[SDK 数据披露](https://developers.google.com/ml-kit/android-data-disclosure)、[模型安装方式](https://developers.google.com/ml-kit/tips/installation-paths)
- 约束：OCR 接口与实现隔离；锁定模型、SDK 版本和许可，列出下载及遥测行为、端点、字段、开关。原片、OCR 内容、帧、草稿不得进入遥测；默认本地制作也不允许非必要指标外传。只有受支持配置可禁用且实际审计通过才采用对应 SDK，否则换可控端侧实现，披露不能代替门禁。不能暗中转云，也不能把“本地推理”宣传成“所有组件零联网”。
- 门禁 G01（F04/A12）：新安装且无历史模型缓存，飞行模式走完分析或明确手工降级；在联网、断网再恢复、冷启动、失败/崩溃场景检查应用及依赖的出站记录，植入隐私样本不得外传。仅“关网能运行”不算网络审计通过。手工降级不能永久代替 P0 OCR，首版仍须验收可用的端侧识别路径。

### R02 复核、输出字节与派生资产发生脱节
- 风险：只给状态打 reviewed=true，重编码、区域裁切、缩略图、撤销旧编辑或并发修改后仍沿用旧批准；源素材还可能进入日志/备份。
- 约束：源媒体 → 固定快照 → 安全编译 → 实际输出重解码 → 人工复核 → 交付的依赖必须可追踪。复核绑定安全资产实际字节摘要、相关文字/坐标、处理器版本；变化只重置受影响项。包清单由白名单产物生成，不遍历整个项目目录。发布提交前重新核对快照、摘要和批准。
- 门禁 G02（F13–F15/F24/A04/A05/A12）：逐一改变底图、尺寸、遮挡、视频范围、文字、裁片、编码器版本或恢复旧编辑，断言正确失效且不可发布。对实际交付物验证中间帧隐私、所有音轨、元数据、未引用文件和缩略图；备份/设备迁移与日志故障注入不得带出敏感内容。自动扫描不能替代必要人工复核。

### R03 ZIP 安全只做了文件名和压缩包大小检查
- 风险：路径穿越、规范化后重名、符号链接、ZIP 元数据谎报、超多小文件、解码后巨幅图以及 JSON 深度都可能绕过简单校验。[Android 路径穿越说明](https://developer.android.com/privacy-and-security/risks/zip-path-traversal)
- 约束：不可信包只进入应用私有隔离目录；统一规范化与去重，拒绝绝对路径/父路径/链接/嵌套归档。流式累计实际解压字节，设置条目数、单文件、路径、JSON 深度和解码像素预算，媒体同时检查魔数、容器和解码结果。完成全部验证后原子加入库。50 MiB 压缩与解压上限均执行，其他安全限额必须在导入模块开工前冻结。
- 门禁 G03（F20/F29/A10/A16）：共享恶意语料覆盖 ../、反斜线、大小写/Unicode 别名、重复路径、链接、未知扩展/伪装媒体、超深 JSON、缺资产、哈希不符、巨幅图与解压炸弹；任何失败不越界写入、不覆盖旧项目，及时终止并清理本次暂存。

### R04 链接撤销仍能从缓存或旧媒体入口取回内容
- 风险：只鉴权 HTML，媒体公开；或 CDN 命中、Range/HEAD/304、旧签名 URL 绕过撤销。缓存语义不能靠一个“no-cache”名称推断。[HTTP 缓存标准](https://www.rfc-editor.org/rfc/rfc9111.html)
- 约束：P0 建议私有对象存储加统一媒体网关，所有请求先检查当前版本状态与有效期，再处理条件请求/Range。不向观看端发可绕过网关的长期对象地址；受限响应默认 no-store，禁止 Service Worker 缓存发布内容。撤销确认须以权威状态提交为准；鉴权存储故障时 fail closed。后续 CDN 若加入，须证明请求级检查没有被缓存越过。
- 门禁 G04（F17/F22/A09）：预热实际存在的浏览器/代理缓存后撤销，GET、HEAD、Range、If-None-Match、缩略图、清单、复制出的旧地址和断点恢复均拒绝新的内容请求；覆盖实际部署的多实例与超时故障，核实 P0 不用滞后副本鉴权。未来引入 CDN 必须追加命中/失效与旁路测试。已下载或已在内存的字节不承诺收回，不能把它当撤销测试失败或远程擦除功能。

### R05 WorkManager 被误当成事务和任意进度续跑
- 风险：进程死亡可能留下半文件、数据库已提交但文件未落地、重复发布；force-stop 与系统杀进程也不是同一种恢复承诺。长任务调度仍受系统限制，Android 16 的长运行 worker 还涉及作业配额。[Android 长任务说明](https://developer.android.com/develop/background-work/background-tasks/persistent/how-to/long-running)
- 约束：应用任务表保存 jobId、快照摘要、阶段、已验证检查点、临时目录和幂等键；调度器只负责触发。以阶段原子提交恢复，允许重做当前未完成片段，不声称任意编码帧无损续跑。重复启动、取消、重启和版本升级有显式状态机；重开应用可重建未完成任务。
- 门禁 G05（F01/F25/A08/A11）：在每个数据库/文件提交边界注入 kill、重启、磁盘满、取消和上传回执丢失；恢复后已保存编辑不丢、零半成品成功状态、零重复资产/链接、旧版本可用。分别报告后台回收和 force-stop 后重新打开的行为。

### R06 Kotlin 与 TypeScript 各自实现“相同”合同但实际漂移
- 风险：JSON Schema 只能覆盖部分语义；默认字段、未知键、重复 JSON key、数字边界、时间舍入、排序与摘要序列化差异会产生两端各自合法的不同作品。
- 约束：一份版本化交换 schema、配额源、语义规则和 golden fixtures；Kotlin/TS 各自实现但同语料验收。明确整数安全范围、坐标容差、半开时间区间与一次舍入、图排序、规范化 JSON/摘要输入。原文件哈希和语义摘要分开命名；版本不支持就拒绝，不能静默丢字段。
- 门禁 G06（F19/F26–F29/A13–A16）：在相同受支持 schema/策略及共有语义范围，合法/非法语料在 Android、Web、服务端、Remotion 上接受/拒绝与错误码一致；exportKind/能力支持差异另列预期矩阵。序列化往返不改语义；有限回访、重叠转场、边界坐标及总帧数 golden 一致；对每项限额测试等于上限与超一单位。

### R07 手机长时媒体管线只在模拟器跑通
- 风险：5 分钟、60fps、1080×2400 输入若囤积帧，内存和临时磁盘急剧增长；热降频、电量低、前后台切换及厂商编码器会让看似成功的导出不可用。Remotion 留在桌面不消除手机安全重编码成本。
- 约束：有界流式解码/编码、单任务或明确受限并发、缩略图缓存预算；事先估算源副本＋输出＋暂存峰值空间；低电量/过热可暂停到安全检查点。热信号可能不可用，须有未知状态降级而非假定正常。[Android Thermal API](https://developer.android.com/games/optimize/adpf/thermal)
- 门禁 G07（F02/F10/F25/A11）：最低支持真机与主流设备跑推荐样本、规格上限、连续多次处理；记录 PSS/峰值内存、临时盘峰值、耗时、热状态、电量变化和取消响应。包含低存储、低电量、系统后台限制、编码失败；阈值由小样基线冻结，没有冻结阈值和真机证据不得宣布性能通过。

### R08 发布事务、授权与版本配额并发不一致
- 风险：客户端显示 4 个有效版本，两次并发发布变成 6 个；回执丢失生成第二版；资源未就绪就公开，或另一账号猜 ID 后撤销。
- 约束：发布会话、上传暂存、清单验证和正式版本激活分离；服务器按所有者＋项目＋幂等键去重，配额在事务中计算并预留/核销。ACTIVE 仅指完整、验证过的不可变快照；所有管理动作服务端检查所有权。到期以服务器时钟为准；撤销不可被重试发布复活。
- 门禁 G08（F21–F23/A08/A09）：从 4 个有效版本并发提交多次，只允许政策内的有效数量；相同键/不同内容冲突有明确错误。覆盖回执丢失、上传部分成功、两账号 IDOR、撤销与完成竞争、到期边界和清理任务重跑；旧版内容及有效期始终不变。

### R09 数据包或 AI 回写突破可信播放器边界
- 风险：看似说明文字成为 HTML，包中 URL 被适配器下载；AI 改回 reviewed=true；播放回调乱序、环或历史恢复跨版本引出未声明路径。
- 约束：包永远是数据，外部文字按纯文本渲染，禁止远端资源、表达式、动态 import 和危险 URI。Remotion 模板、字体和白名单效果由受信发行提供，输入不修改执行入口；AI 回流新建草稿、清除外部批准。播放器用显式状态机及本次转移 ID，忽略取消后旧视频回调；自动边构成的环禁止，用户环须有出口。
- 门禁 G09（F09/F16–F18/F28/F29/A02/A13–A16）：恶意标签/URL/脚本无执行和网络请求；依赖已就绪后的模板离线运行不向外取字体或媒体；A→B→D 与 A→C→D 历史正确，连点/跳过/返回/过期回调不串线；AI 输入永不覆盖或自动发布，未知效果和无限路径明确失败。

### R10 PR 批准与发布证据不真实
- 风险：单人项目写“一人独立批准”却由作者本人、同一身份的 AI 或机器人绕过；文档/编译通过被包装成 P0 已验收。GitHub 明确 PR 作者不能批准自己的 PR。[GitHub 审批规则](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/approving-a-pull-request-with-required-reviews)
- 约束：先声明多人或单维护者治理。多人要求非作者有效审批；单维护者明确记录自审、自动检查和针对该提交的风险接受，不能声称独立 review。AI 辅助评审不计真人独立审批。是否允许单维护者例外必须明确决定，不静默绕过 branch protection；安全/隐私高风险发布的独立审查要求另列为 release gate。
- 门禁 G10：proposals PR 只标“方案待批准”；实现 PR 附 F/A 追踪、最终 commit SHA 与实际检查结果，分别列通过/失败/未运行。核实实际 ruleset、审批者与最新 SHA，提交变化后重新验证；产品 release 需 G01–G09、A01–A16、真机及兼容报告，不能以 draft PR 已创建替代验收完成。

## 交叉审查结论

已审范围：产品规格 v0.1；docs/proposals/0001-architecture.md 技术架构提案；docs/engineering/engineering-standard.md 工程规范。两份提案的关键不变量与 G01–G10 已对齐，工程规范第 6.3 节给出门禁映射；架构验证计划采用 V01–V07，避免与风险门禁混号。

- 已纳入设计：SDK 出站审计、实际输出复核、流式安全解包、JCS/跨语言语料、持久任务和文件/数据库 journal、强一致媒体访问、发布额度预留、私有对象两阶段提交、AI 数据与受信模板分离、单维护者真实自审及最终 SHA 证据。
- 已修正边界：手机完成创作、导出和回流，F28 实际渲染在桌面验证；本机私有源素材回看与安全交付预览分别允许和隔离；低电量/热压力/未知热信号、临时盘峰值与连续处理均进入验证计划。
- 尚待批准或冻结：OCR 最终实现及非必要指标禁用可行性；最低机型/系统/浏览器与性能阈值；解包条目数、JSON 深度、解码像素、AI visits/总时长等策略限额；托管供应商、地区、保留和恢复目标；真实仓库保护与审查模式。
- 审查结论只表示方案覆盖了关键约束。产品尚未落地，G01–G09、A01–A16、真机、媒体重编码、渲染、网络与恢复测试均未运行；G10 的本次仓库/文档检查证据见[入库记录](../engineering/repository-adaptation.md)和当前 PR，完整治理门禁尚未完成；不能据此给产品安全或可发布结论。

## 合并建议

先批准边界、契约、信任模型和证据门禁，再批准模块实现。所有“支持/安全/恢复/性能”描述必须区分设计承诺与测得结果；安全门禁不能因赶展示时间改成警告继续。
