# 固定测试签名与重签核对

本目录只含无秘密说明与 Python 标准库脚本。签名由维护者在已授权环境完成；使用者只接收已核对的 APK，无需配置签名工具或密钥。这里不生成凭据，也不包含实际密钥路径、密码或私钥。

已批准的开发测试证书公开 SHA-256 指纹：

```text
0929d62a4336760a8c0395cea92c6e9b272c897f02b126f84f5f0a4e0a4fefc2
```

这是专用开发测试证书，不是正式发布或旧版 CI 调试证书。

## 维护者的一条命令

可信 Android SDK Build Tools 的 `apksigner` 已可用且支持 `--lib-page-alignment` 时，在仓库根目录执行：

```sh
python3 tools/signing/sign-development-apk.py CI_INPUT.apk SIGNED_OUTPUT.apk --signing-dir SIGNING_DIR
```

`SIGNING_DIR` 是维护者显式指定的仓库外目录，必须已有 `development.p12` 与 `store.pass`。脚本不创建或轮换密钥；只把既有凭据文件交给 `apksigner`，使用 `file:` 密码输入，不打印口令或私钥。不需要终端交互、CI 密钥配置或用户安装工具。若 SDK 工具未在 PATH 中，维护者可用 `APKSIGNER` 环境变量指定可信 `apksigner` 可执行文件，不要填整条 shell 命令。

脚本启用 v2/v3 签名，关闭 v4/独立 `.idsig`，要求 16384 字节原生库页对齐。它先在临时目录完成签名、`apksigner verify --verbose --print-certs`、唯一签名证书的上述固定指纹核对及内容/对齐检查，全部通过后才生成最终文件。输入保持原样；输出不得与输入同路径或已存在，即使输出在检查后被其他进程创建，也会拒绝覆盖。不会自动下载工具、获取 APK、安装应用或卸载旧版。失败时不交付输出；签名工具的原始日志不回显，以避免泄漏凭据。

## 最小交付流程

1. 从目标提交成功的 `ci/gate` 下载现有兼容预览 APK，保留原件，并记录提交、运行与产物来源。先用 Android SDK 的 `apksigner verify --verbose --print-certs` 检查原件。CI 调试证书只标识原件，不是后续固定测试证书。
2. 在本地用 `apksigner sign` 和同一把专用测试密钥重签，通过 `--out` 写到新文件，绝不原地覆盖输入。密钥保存在仓库外，不加入 Git、CI 配置、构建产物或交付附件。密码通过维护者已有的安全输入方式提供，不写进命令、文档或日志。
3. 对输出执行 `apksigner verify --verbose --print-certs`，要求验签成功，并把输出的证书 SHA-256 指纹与此前独立保存的固定测试证书公开指纹逐字核对。首次使用时记录该公开指纹；后续不能拿待验 APK 自报的指纹重新定义预期值。
4. 在仓库根目录运行下列命令。它不需要密钥，输入和输出必须是不同文件；任一失败都先停下排查，不交付。

   ```sh
   python3 tools/signing/verify-resigned-apk.py CI_INPUT.apk SIGNED_OUTPUT.apk
   ```

5. 交付已核对的输出 APK、其文件 SHA-256、公开证书 SHA-256、对应提交及验证结论。公开证书指纹和 APK 文件摘要是两个不同值。构建通过、验签通过和真机安装/运行结果分别记录。

`CI_INPUT.apk` 与 `SIGNED_OUTPUT.apk` 只是文件占位名。重签使用维护者已配置的固定密钥；本说明不要求使用者创建账户、录入密码或改 CI。不要把一次性 CI 调试密钥当作稳定更新签名。

若输入的存储对齐不合格，先排查构建或用 Android SDK 的 `zipalign -P 16` 在签名前生成对齐副本，并保留最初 CI 原件供内容追溯；不要改已签名输出。此脚本严格检查两个输入文件，原件自身不合格时不会放行，需另行核对原件与对齐副本的内容一致性后，再验证对齐副本与重签结果。

## 脚本实际检查的范围

- 遍历输入与输出全部 ZIP 条目，包含目录；拒绝重复名称、歧义名称、加密条目、损坏或无法读取的条目。
- 非签名条目的名称集合不得增加或删除；逐条流式读取解压后全部字节，比对大小、SHA-256 和压缩方式。不会把仅重签的结果当作新功能构建。
- 只允许 `META-INF/` 直属的 `MANIFEST.MF`、`*.SF`、`*.RSA`、`*.DSA`、`*.EC` 签名条目改变或增删，按 JAR 约定忽略这些名称的大小写。其余 `META-INF` 内容照常核对；嵌套路径及 `SIG-*` 文件也没有额外豁免。被排除条目仍检查可读性、重复名与适用的对齐要求。
- 从每个条目的本地 ZIP 头计算真实数据起始偏移。输入和输出所有未压缩（stored）条目必须 4 字节对齐，其中 `lib/` 下名称以 `.so` 结尾的未压缩条目必须 16 KiB（16384 字节）对齐；不会用中央目录的额外字段长度代替本地头长度。
- 成功退出码为 `0`，核对失败为 `1`，命令行参数错误为 `2`。成功时列出排除的签名文件及两个 APK 的文件 SHA-256。

这只是重签后的内容与 ZIP 布局辅助核对。APK v2/v3 签名块不是 ZIP 文件条目，本脚本不解析或认证它们；无签名的 ZIP 也可能通过内容核对。它不能替代 `apksigner verify`、独立的预期证书比对、包名/版本核对、ELF 段对齐检查、Android 安装或真机运行验证；ZIP 的 16 KiB 对齐也不等于已完成 16 KiB 页大小设备兼容测试。

## 首次换签与版本边界

- 当前兼容预览包名保持 `com.tapscene.preview.hevc`。当前构建配置 `versionCode = 4`，高于已发旧包的 `3`；维护者仍需核对下载 APK 的实际包名和版本，脚本不解析 Android 清单。
- 版本号增加不能解决证书不同的问题。首次从旧的临时调试签名换成专用测试签名，不能直接覆盖旧包。不要自动卸载旧版、清除数据或另增包名来绕过冲突；遇到冲突先保留旧包与本机项目，说明情况并等用户决定。当前项目导出/迁移尚未实现，不能承诺卸载后能恢复。
- 此后只有在包名、固定签名及版本条件均满足时才具备覆盖更新的前提，实际安装仍需验证。后续每次交付继续核对同一公开证书指纹。
- 开发云环境不是可靠的密钥备份。密钥及必要恢复材料需要另行授权的持久、安全保管安排；未核实恢复能力前，不承诺环境重建后仍能使用同一签名。公开指纹不能恢复私钥，不能替代备份。
