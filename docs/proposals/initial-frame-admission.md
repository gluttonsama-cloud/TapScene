# 首次点击的画面准入

状态：设计已审，最小实现与主机回归进行中；没有新增设备运行授权。

## 行为与选择语义

首次手势尚未派发时，在原确认起算的 15 秒内等待一份可精确关联的初始画面。目标、几何、录制、通知和锁屏守卫保持原样。后续动作之间及末尾的 waitAfter 不增加等待。

选择的是**准入时的初始快照**：准入请求后的下一个正常呈现 tick 在 GL 队列中固定当时真实最新的 FBO，沿用该 tick 的呈现时钟及源帧原始 canonical 绑定；等待这一源的原始 EGL 提交和精确 mux 样本。较新帧继续正常呈现，但不能替换已选快照。若该 tick 为静态重复，其 tick PTS 与原始 canonical PTS 分别保留，重复样本不能救回原始缺失匹配。

这避免持续新帧导致“永远追赶最新匹配帧”。它不声称画面是派发瞬间最新，也不能证明目标没有在选择后变化。选择、消费与确认截止时间作为私有诊断元数据保留；uptime 不参与 PTS 换算。主视频包含真实准入准备时长。

## 最小状态转移

| 状态 | 允许操作 | 退出条件 |
| --- | --- | --- |
| Ready / 等待首次准入 | 仅一个、按完整动作/会话/来源/generation/epoch/确认身份绑定的请求 | 原始样本匹配后开始引擎；取消、未知窗口或截止则不派发 |
| 已选快照 / 等待原始匹配 | 最多一个 FBO 租约，无 Bitmap；正常视频持续输出 | 精确原始提交和 mux 同时成立；不能换绑后续重复样本 |
| Running / 已记录唯一 Intent | 原有 Started、DispatchIntent 各一次；fsync 后仍让主线程处理窗口事件 | 再核 arm 身份/截止、守卫和会话，消费同一快照 |
| 已消费 Before | 租约转交原 PNG 管线，消费唯一 pendingDispatchToken | 平台短按最多一次；若重入取消则结束，不能重新打开该边界 |
| 后续动作 | 沿用现有 before/after、等待及 Missing 合同 | 不引入全链路新引擎 |

等待的唯一通知需合并并调回主线程，不阻塞 main/GL/codec。不匹配时保留 Pending，不生成最终 Missing。超时/停止不重新选另一张以凑通过。暂停撤销请求并关闭 epoch；只有用户明确确认恢复才可新建请求。已有 durable Intent 保留同一个未调用 token，不再记 Started/Intent；进程恢复仍视意图结果未知，不重试。

## API 与归属

- 独立 `InitialFrameAdmissionPort.begin(action, authorization, onChanged)` 返回唯一取消句柄。句柄提供状态、一次 consume 和 cancel；不会复用可选证据接口的 `None` 当作放行。
- 后端拥有实际租约、请求和截止；协调器只提供绑定当前 session 的代理，停止门禁同步撤销。GL 正常呈现选帧，EGL/mux 两种到达顺序均可完成精确匹配。
- 引擎 Ready 时等待；意图落盘后的通知只恢复同一个待派发 token。消费前后仍核对取消与守卫，不吞掉首次准入失败。
- ClickPlayback 保留原 arm 至第一手势真正调用前，显示“核对初始画面，尚未派发”；普通暂停/后续恢复路径保持现有限制。
- 私有 evidence v2 仅增加首次快照 provenance，包含选择种类、选择/消费 uptime、选择 tick ID/PTS 和原确认截止；继续读 v1。旧 reader 必须拒绝 v2，不能把新快照语义误当作旧即时 before。点击计划和 legacy Mapping.Unknown 不回写。
- 外发合同只说明画面依据：真实快照仍为 recorded，人工确认的热点/继续边仍为 authored；现有 schema 没有原始派发 Before/After 时间字段。复核页明确初始快照语义，私有导入重试摘要纳入新 metadata；不新增外发时序字段，不更改 DB/包版本，不阻断正常观看包/AI 包。

## 必须覆盖的边界

1. 新帧持续到来不替换快照；提交与 mux 乱序仍只认可同一原始样本；重复输出不能救原始缺失。
2. 唯一 Started/Intent/平台调用；等待不压缩动作间或末尾 wait；同步/迟到/重复通知不会重放。
3. 等待与消费时的截止、未知窗口、几何变化、停止、录制丢失及旧确认回调均阻断；恢复前不自动新建请求。
4. 取消/消费/PNG 失败各自精确归还一次租约，最多一份准入 pin；全局仍三 FBO、两 PNG 许可。
5. v1 兼容、v2 选择元数据持久化/校验，原始 canonical 与 selection tick 不能混用；原图仍须正常封口、来源登记和候选复核。

当前第四次实测的缺失分支仍不可判定。本设计分别预防选择过早和原始样本尚未核对时即开始第一手势，不追认旧产物，也不保证后续所有边界或 PNG/封口均成功。
