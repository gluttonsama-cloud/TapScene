## 开发规则

- 一次解决一个明确问题，使用任务分支和 Draft PR；标题为英文类型加中文，正文只写具体改动。
- main 经 PR，分支保持最新，最新 `ci/gate` 通过且讨论已解决；合并、部署和权限变更按相应授权执行。
- 按改动做必要增量检查，优先运行功能并看实际效果；安全、数据和恢复改动检查对应反例，结果按真实状态填写。
- 产品范围、隐私、费用或破坏性迁移有重要取舍时先说明并确认；界面交付真实操作、数据和进度。

- 入口：单步画面“替换画面”与遮挡“重新遮挡”；同一画布调帧、遮挡、实际输出复核，确认后替换原步骤，不另建步骤或要求重连。

## 单步一次撤销增量

| 范围 | 行为 |
|---|---|
| 编辑 | 未保存的文字、终点、热点与下一步动作可撤销最近一次；同字段连续输入合并，失焦或换字段结束合并；画布拖动一次计一次。 |
| 面板 | 直接恢复同一暂存表单的原始输入，包括尚未有效的数值；打开或取消面板结束旧历史，取消后的输入不会复活。 |
| 保存与恢复 | 撤销后重新自动暂存，失败保留恢复后的输入并可重试。保存失败保留撤销；成功保存、放弃、离步、重开或正式修订变化清空历史。 |
| 安全 | 仅内存白名单作者字段，无新表或迁移；撤销重读修订并核对当前目标，媒体只来自当前正式步骤，不恢复历史图片、区域、过渡或复核。 |
| 核验 | 新增单个原生 SQLite/Workspace 边界检查，复用四张小屏/横屏生产 Compose 渲染；以本 PR 最新 CI 为准。真机触控、输入法和生命周期待设备核验。 |

## 预编排点击链录屏增量

- 主流程：编辑顺序短按点及等待 → 在目标 App 定位 → 确认定位窗口已脱离 → 用户核对起始页、授权完整默认屏幕录制 → 录屏及目标全屏窗口就绪 → 串行播放一次 → 保存真实 MP4、不可变完整计划与独立私有执行日志。
- 持久协议：稳定 planId/actionId、revision/digest、目标 App、default display 尺寸/方向，runId/sessionId/sourceId/generation 隔离回调；派发前同步写 intent，系统接受、拒绝、完成、取消和超时分别记录。完成回调只表示手势完成；未知结果不重试。手动取帧校正继续可用。
- 暂停只阻止后续点，已派发短按可能完成；恢复需要重新确认当前页。停止、进程中断、权限失效、几何变化终止本轮；录屏封口登记重试不重放。服务无启动/重启续播入口。
- 权限：点击链需 API33+ 的窗口显示器标识（API26–32 保留手动录屏）；用户亲自启用仅手势能力的无障碍服务，TYPE_ACCESSIBILITY_OVERLAY 提供定位；不增加 SYSTEM_ALERT_WINDOW、QUERY_ALL_PACKAGES、节点读取或键盘过滤。仅活跃编排/播放期间读取窗口包名、类名、全屏状态，窗口轨迹不落盘。未知窗口暂停；同 App 敏感页面不能全面识别，页面明确提示仅普通演示用途。
- 验证：增量假执行器/持久恢复/窗口守卫和真实 Compose 预览随本 PR CI；实际通过以精确最终提交为准。无 SDK/KVM 的本机不声称通过真实 dispatch、覆盖层录屏消失、OS 中断、坐标/insets 或平台录制验证。
